Инструкция: добавление нового коннектора в витрину

Пошаговое руководство для администраторов и разработчиков
Версия: 2026-09-01 · Для корпоративного форка OpenCode

Кратко: чтобы добавить коннектор, нужно 4 шага — описать сервер в catalog.yaml, создать файл разрешений в permissions/, скопировать оба файла в Hub-контейнер, и перезапустить Hub. После этого коннектор появится в витрине у всех пользователей.

Структура файлов Hub

opencode-mcp-hub-i3/ ├── catalog.yaml ← каталог всех коннекторов ├── permissions/ │ ├── tag.yaml │ ├── jira.yaml │ ├── confluence.yaml │ ├── outlook.yaml │ └── {новый_коннектор}.yaml ← создать ├── deploy/ │ ├── .env ← переменные окружения │ ├── docker-compose.yml │ └── docker-compose.local-http.yml └── src/hub/

Шаг 1. Описать сервер в catalog.yaml

1
Добавить запись в каталог

Откройте ~/Documents/opencode-mcp-hub-i3/catalog.yaml и добавьте новый элемент в массив servers.

Шаблон для facade-сервера (с personal_token)

  - alias: gitlab                    # уникальный идентификатор
    type: "MCP"
    title: "GitLab"                   # название в витрине
    summary: "Merge requests, issues, pipelines"
    icon_color: "#FC6D26"             # цвет иконки (hex)
    description: |
      GitLab — система управления репозиториями Магнита.
      Подключив его, вы даёте ассистенту доступ к MR, issues,
      pipeline и коду проектов.
    owner: "AI Lab"
    contact: "https://copilot-portal.ailab-copilot-prod.corp.tander.ru"
    docs_url: "https://docs.gitlab.com"
    docs_label: "GitLab Docs"
    status: "beta"                    # beta | ga
    audience: ['all']                 # ['all'] или список групп
    mode: facade                      # facade (через Hub) | native (напрямую)
    upstream_url: "${GITLAB_MCP_URL}" # адрес MCP-сервера
    auth_methods:
      - id: personal_token
        title: "Personal Access Token"
        type: user_token
        field:
          label: "GitLab PAT"
          hint: "Создайте токен в GitLab → Settings → Access Tokens"
          secret: true
        verify:
          url: "https://gitlab.corp.tander.ru/api/v4/user"
          method: GET
          headers:
            PRIVATE-TOKEN: "{{access_token}}"
          account_field: "username"
          require_account: true
    credential_headers:
      PRIVATE-TOKEN: "{{access_token}}"
    permission_model:
      kind: tool_filter
      presets:
        readonly:
          tools:
            - list_projects
            - get_project
            - list_merge_requests
            - get_merge_request
            - list_issues
            - search_code
        readwrite:
          tools:
            - "*"

Поля catalog.yaml — справка

  • alias — уникальный идентификатор, используется в URL и API
  • mode: facade — Hub проксирует запросы, подставляя токен
  • upstream_url — адрес MCP-сервера (может быть env-переменная ${...})
  • auth_methods[].type: user_token — direct-token (PAT/пароль)
  • auth_methods[].type: oauth2 — OAuth flow (будущее)
  • auth_methods[].verify — как Hub проверяет токен при подключении
  • credential_headers — заголовки, которые Hub подставляет при проксировании
  • permission_model.kind: tool_filter — фильтр по списку инструментов
  • permission_model.kind: header_groups — группы с allow/ask/deny
Важно: verify.url выполняется из Docker-контейнера Hub. Используйте 127.0.0.1:8000 для self-check или корпоративный DNS-адрес для внешних систем. Не используйте localhost:8080 — это порт хоста, недоступный из контейнера.

Шаг 2. Создать файл разрешений

2
Создать permissions/{alias}.yaml

Файл разрешений описывает инструменты коннектора и их классы (read_only / write_delete).

# permissions/gitlab.yaml
# version: 2 — раздел `tools` со строкой на каждый инструмент.
version: 2
groups:
  - id: project_read
    title: "Читать проекты и код"
    description: "Список проектов, MR, issues, поиск по коду."
    default: allow
    tools:
      - list_projects
      - get_project
      - list_merge_requests
      - get_merge_request
      - list_issues
      - search_code
  - id: project_write
    title: "Создавать и менять MR, issues"
    description: "Создание MR, комментариев, issues, назначение ревьюеров."
    default: ask
    tools:
      - create_merge_request
      - update_merge_request
      - create_issue
      - update_issue
      - add_comment
  - id: ci_write
    title: "Запуск pipeline и jobs"
    description: "Запуск и перезапуск CI/CD pipeline."
    default: deny
    tools:
      - run_pipeline
      - retry_job
      - cancel_job
rest:
  title: "Остальные инструменты"
  description: "Появятся в будущем или экспериментальные."
  default: ask
tools:
  list_projects:
    title: "Список проектов"
    class: read_only
  get_project:
    title: "Данные проекта"
    class: read_only
  list_merge_requests:
    title: "Список MR"
    class: read_only
  get_merge_request:
    title: "Данные MR"
    class: read_only
  list_issues:
    title: "Список issues"
    class: read_only
  search_code:
    title: "Поиск по коду"
    class: read_only
  create_merge_request:
    title: "Создать MR"
    class: write_delete
  update_merge_request:
    title: "Обновить MR"
    class: write_delete
  create_issue:
    title: "Создать issue"
    class: write_delete
  update_issue:
    title: "Обновить issue"
    class: write_delete
  add_comment:
    title: "Комментарий"
    class: write_delete
  run_pipeline:
    title: "Запустить pipeline"
    class: write_delete
  retry_job:
    title: "Перезапустить job"
    class: write_delete
  cancel_job:
    title: "Отменить job"
    class: write_delete

Правила разрешений

  • default: allow — инструмент работает без подтверждения
  • default: ask — UI спрашивает пользователя перед каждым вызовом
  • default: deny — инструмент заблокирован
  • class: read_only — не меняет данные (для preset readonly)
  • class: write_delete — меняет или удаляет данные (для preset readwrite)
  • rest.default — применяется к инструментам, которых нет в файле

Шаг 3. Добавить env-переменные (если нужно)

3
Добавить переменную в .env

Если upstream_url использует ${...}, добавьте переменную в deploy/.env:

# deploy/.env
GITLAB_MCP_URL=http://host.docker.internal:8082/mcp

Для локального MCP-сервера (на машине разработчика) используйте host.docker.internal. Для серверного MCP — внутренний Docker DNS или корпоративный адрес.

Шаг 4. Загрузить в Hub и перезапустить

4
Скопировать файлы и перезапустить Hub
# Скопировать файл разрешений в контейнер
docker cp ~/Documents/opencode-mcp-hub-i3/permissions/gitlab.yaml \
  hubi3-hub-1:/app/permissions/gitlab.yaml

# Перезапустить Hub (catalog.yaml примонтирован как bind mount)
docker restart hubi3-hub-1

# Дождаться запуска
sleep 5

# Проверить, что коннектор появился
KEY=$(python3 -c "import json; d=json.load(open('$HOME/.local/share/opencode/auth.json')); print(d['magnit_prod']['key'])")
curl -s "http://localhost:8080/api/catalog" \
  -H "Authorization: Bearer $KEY" | python3 -c "
import json, sys
d = json.load(sys.stdin)
for s in d.get('servers', []):
    print(f'  {s[\"alias\"]}: {s.get(\"connection\",{}).get(\"status\",\"not_connected\")}')
"
Готово! Коннектор появился в каталоге. Все пользователи увидят его в витрине при следующем запуске Desktop-приложения (или после обновления кэша каталога).

Шаг 5. Запустить MCP-сервер (если локальный)

5
Запустить MCP-сервер коннектора

Если MCP-сервер работает локально (как outlook-ews-mcp), запустите его:

cd /path/to/gitlab-mcp
source .venv/bin/activate
nohup env MCP_TRANSPORT=sse MCP_SSE_HOST=0.0.0.0 MCP_SSE_PORT=8082 \
  gitlab-mcp > /tmp/gitlab-mcp.log 2>&1 &

Для серверного развёртывания — добавьте сервис в docker-compose.yml или Helm-чарт.

Чек-лист

  1. ☑ Запись в catalog.yaml: alias, title, mode, upstream_url, auth_methods, verify, credential_headers, permission_model
  2. ☑ Файл permissions/{alias}.yaml: группы, инструменты, классы
  3. ☑ Переменная {ALIAS}_MCP_URL в deploy/.env
  4. ☑ docker cp permissions/{alias}.yaml hubi3-hub-1:/app/permissions/
  5. ☑ docker restart hubi3-hub-1
  6. ☑ Проверка: GET /api/catalog показывает новый коннектор
  7. ☑ MCP-сервер запущен и доступен по upstream_url
  8. ☑ Verify URL доступен из Docker-контейнера Hub

Частые проблемы

Коннектор не появился в каталоге

  • Проверьте логи: docker logs hubi3-hub-1 2>&1 | grep -i error
  • Возможно, YAML невалидный — Hub молча дропает сервер с ошибкой схемы
  • Проверьте, что upstream_url раскрывается (env-переменная существует в контейнере)

Подключение зависает

  • verify.url недоступен из контейнера Hub — используйте 127.0.0.1:8000/health для self-check или корпоративный DNS
  • Не используйте localhost:8080 в verify — это порт хоста, недоступный из контейнера

Инструменты не показываются (tools: 0)

  • Файл permissions/{alias}.yaml не скопирован в контейнер
  • Имена инструментов в файле не совпадают с именами в MCP-сервере
  • Hub не перезапущен после копирования permissions

MCP-вызовы возвращают ошибку

  • Проверьте, что MCP-сервер запущен и отвечает по upstream_url
  • Проверьте, что credential_headers корректно подставляют токен
  • Проверьте логи MCP-сервера
