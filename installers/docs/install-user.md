# Установка OpenCode Magnit — инструкция пользователя

Документ описывает установку корпоративной сборки OpenCode из пакета, скачанного с портала AI Lab.
Всё, что нужно, лежит внутри пакета: интернет установщику не требуется.

---

## Что делает установщик

Порядок шагов фиксирован, каждый шаг печатается в отчёт:

1. **Проверяет аргументы командной строки** и режим запуска.
2. **Читает и проверяет `common/manifest.json`** — состав пакета, версию, ОС и архитектуру,
   контрольные суммы файлов. Любая ошибка в манифесте останавливает установку до того,
   как что-то изменится в системе.
3. **Сверяет ОС и архитектуру** пакета с вашей системой. Пакет для другой ОС или другой
   архитектуры не устанавливается.
4. **Ставит корпоративный CA** в каталог конфигурации:
   - macOS и Linux: `~/.config/opencode/tander-ca-bundle.pem`
     (или `$XDG_CONFIG_HOME/opencode/…`, если переменная задана);
   - Windows: `%USERPROFILE%\.config\opencode\tander-ca-bundle.pem`.
5. **Ставит бинарник `opencode`** и добавляет его каталог в `PATH`:
   - macOS и Linux: `~/.local/bin/opencode`, переменные `NODE_EXTRA_CA_CERTS` и `PATH`
     дописываются в файл профиля вашей оболочки внутрь блока с маркерами
     `# >>> opencode-magnit >>>` … `# <<< opencode-magnit <<<`. Правится **только** этот блок:
     если его в файле ещё нет, он добавляется в конец, а если он уже есть — обновляется **на
     месте**, оставаясь там, где стоял; ваши собственные строки и их порядок не меняются.
     Блок в файле всегда ровно один: случайно задвоенные копии очередной запуск схлопывает
     в одну. Если файл профиля уже существовал, перед первой вставкой блока рядом создаётся
     резервная копия `<файл профиля>.opencode-magnit.bak`;
   - Windows: `%LOCALAPPDATA%\Programs\opencode\opencode.exe`, переменная пользователя
     `NODE_EXTRA_CA_CERTS` и пользовательский `PATH` (переменные уровня системы не трогаются).
6. **Ставит Desktop-приложение**, если оно входит в пакет (macOS — из `.dmg` в `/Applications`,
   Windows — штатным установщиком). Для Linux Desktop не собирается.
7. **Проверяет пользовательский конфиг.** Если `opencode.json` уже есть, рядом создаётся
   ровно одна резервная копия `opencode.json.bak`; сам файл не изменяется.
8. **Печатает итог** и, если не задан `--no-launch`, показывает вывод `opencode corp status`.

Перед копированием или запуском **каждого** файла из пакета установщик сверяет его sha256
с манифестом. Несовпадение — отказ: файл не копируется и не запускается.

## Чего установщик не делает

- **Не спрашивает ключей, паролей и токенов** — их вообще нет в его коде. Файл `auth.json`
  не читается и не создаётся.
- **Не меняет ваш `opencode.json`** — адрес Hub, провайдер и модель зашиты в саму сборку.
- **Не требует прав администратора** при установке по умолчанию. `sudo` вызывается только
  при явном флаге `--system` (установка в `/usr/local/bin`).
- **Не ходит в сеть**: ничего не скачивает, репозиториями и пакетными менеджерами не пользуется.
  Единственное сетевое действие — информационный `opencode corp status` после установки.
- **Не импортирует CA в системное хранилище сертификатов** — ставится только пользовательская копия.
- Не задаёт переменных окружения для GUI-приложений на macOS и Linux (см. «Известные ограничения»
  в `install-admin.md`): Desktop берёт CA из каталога конфигурации.

## Запуск

### macOS

```bash
tar -xzf opencode-magnit-darwin-arm64-<версия>.tar.gz
cd opencode-magnit-darwin-arm64-<версия>
bash install.sh
```

### Linux

```bash
tar -xzf opencode-magnit-linux-x64-<версия>.tar.gz
cd opencode-magnit-linux-x64-<версия>
bash install.sh
```

### Windows

Распакуйте `opencode-magnit-windows-x64-<версия>.zip` и **дважды щёлкните по `install.bat`**.
Из командной строки то же самое: `install.bat` (можно с флагами, например `install.bat -Check`).

## Предупреждения безопасности при первом запуске

Сборки пилота **не подписаны** (подпись Authenticode и Developer ID — решение ИБ, R-14 и D-7:
до него обход предупреждений описан здесь и действует только на время пилота).

**macOS, Gatekeeper.** При первом запуске Desktop-приложения система скажет, что разработчик
не может быть проверен. Откройте «Системные настройки» → «Конфиденциальность и безопасность»,
найдите сообщение о заблокированном приложении и нажмите «Всё равно открыть». Для CLI-бинарника
предупреждение не появляется: он ставится не через браузер и карантинного атрибута не получает.

**Windows, SmartScreen.** При запуске `install.bat` или установщика Desktop может появиться окно
«Windows защитила ваш компьютер». Нажмите «Подробнее» → «Выполнить в любом случае».

Если предупреждение появилось на файле, скачанном не с портала AI Lab, — не запускайте его
и обратитесь в поддержку.

## Первый запуск и вход по SSO

1. Откройте новый терминал (или выполните `source ~/.zshrc` — установщик подскажет нужный файл).
2. Запустите `opencode`.
3. При первом обращении к моделям будет предложен вход по корпоративному SSO: откроется браузер,
   вы входите обычным корпоративным логином. Ключ сохраняется локально, вводить его вручную
   не нужно.

Витрина корпоративных коннекторов (MCP-серверов) — на портале Hub по адресу `/connectors`:
там перечислены доступные серверы и команда подключения каждого.

## Как проверить установку

```bash
install.sh --check      # Windows: install.bat -Check
```

Команда ничего не меняет и печатает построчный отчёт: версия пакета, состояние бинарника,
`PATH`, CA, переменной `NODE_EXTRA_CA_CERTS`, Desktop и адрес Hub. Итоговая строка —
`Итог: всё установлено` или `Итог: требуется установка`.

Состояние корпоративной сборки после входа:

```bash
opencode corp status
```

## Как удалить

```bash
install.sh --uninstall              # удалить программу
install.sh --uninstall --purge      # удалить и пользовательские данные
```

`--uninstall` убирает бинарник, его резервную копию, блок из файла профиля, CA и запись в `PATH`.
Ваши `opencode.json`, `opencode.json.bak` и `auth.json` при этом **сохраняются**.
`--purge` дополнительно удаляет каталоги пользовательских данных, перечисленные в манифесте
(каталог конфигурации и каталог данных) — вместе с сохранённым ключом.

**Про Desktop-приложение.** На macOS оно удаляется вместе с остальным. На Windows установщик
запускает штатный деинсталлятор приложения и дожидается его завершения; если приложение в списке
установленных программ не зарегистрировано, вы увидите строку «Desktop: удалите вручную через
«Приложения и возможности»» — сделайте это сами, остальное уже удалено. Если деинсталлятор
завершился с ошибкой, установщик напечатает «Desktop: ошибка (код N)» и вернёт код `1`: CLI при
этом уже удалён, вручную останется снять только само приложение.

Посмотреть, что будет сделано, не делая этого:

```bash
install.sh --dry-run                # план установки
install.sh --dry-run --uninstall    # план удаления
```

## Если что-то пошло не так

Установщик всегда возвращает код выхода:

| Код | Значение | Что делать |
|---|---|---|
| `0` | успех (для `--check` — всё установлено) | — |
| `1` | непредвиденная ошибка выполнения, в том числе неуспех шага Desktop (при установке — не поставился, при `--uninstall` — не отработал деинсталлятор) | CLI уже установлен (или уже удалён) и остальное сделано; с Desktop разберитесь вручную |
| `2` | ошибка аргументов или манифеста | проверьте флаги; скачайте пакет заново, если манифест повреждён |
| `3` | несовместимая среда: чужая ОС или архитектура, старый PowerShell, нет утилиты хеширования | скачайте пакет для своей системы; на Windows нужен PowerShell 5.1 или новее |
| `4` | не совпал sha256 файла из пакета | пакет повреждён или подменён: скачайте заново, сверьте `SHA256SUMS` |
| `5` | нет прав на запись в каталог установки | ставьте без `--system` (в `~/.local/bin`) или укажите `--prefix` |
| `6` | целевой файл занят другим процессом (Windows) | закройте OpenCode и повторите запуск |
| `7` | только для `--check`: найдены расхождения | запустите установку ещё раз |

Куда обращаться: канал поддержки AI Lab. К обращению приложите полный вывод команды
`install.sh --check` (он не содержит ключей и секретов) и код выхода.
